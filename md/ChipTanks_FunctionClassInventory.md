# ChipTanks 项目 - 主要类与函数清单

## 表1 核心游戏类

| 类名称 | 主要功能 | 说明 |
|--------|--------|------|
| **IRole** | 角色抽象基类 | 所有角色(玩家、敌人)的抽象接口，定义虚函数：`init()`、`think()`、`doAction()`、`drawRole()`、`die()`、`shoot()`、`move()`、`takeDamage()`等 |
| **LeadingRole** | 玩家角色 | 主角坦克，继承IRole，实现玩家操控逻辑、射击机制、碰撞判定 |
| **FeilianEnemy** | 飞廉敌人 | 小型高速敌人(12x12像素)，风神形象，发射普通子弹，群体压迫 |
| **GudiaoEnemy** | 蛊雕敌人 | 中型敌人(15x15像素)，山海经猛禽，高伤害普通子弹，两侧射击，死亡发火球 |
| **ChiMeiEnemy** | 魑魅敌人 | 小型高速敌人(8x8像素)，自杀式冲撞，山林妖怪 |
| **BoEnemy** | 驳精英敌人 | 中型精英敌人(24x24像素)，三种攻击模式：冲锋践踏(MODE_1)、虎牙利爪(MODE_2)、鼓音震荡(MODE_3) |
| **ShengyuEnemy** | 胜遇精英敌人 | 中型干扰型敌人，三种攻击模式：水雾弥漫(MODE_1)、洪波推涌(MODE_2)、赤羽雷鸣(MODE_3)，以干扰视线为主 |
| **LiliEnemy** | 狸力精英敌人 | 中型精英敌人，三种攻击模式：土涌突刺(MODE_1)、獠吠震波(MODE_2)、陷阱伏击(MODE_3) |
| **TaotieEnemy** | 饕餮BOSS敌人 | 大型BOSS敌人，贪食凶兽，复杂AI和多种攻击模式 |
| **TaowuEnemy** | 肉BOSS敌人 | 大型BOSS敌人，肉形凶兽，高血量高伤害 |
| **XiangliuEnemy** | 相柳BOSS敌人 | 大型BOSS敌人，多头蛇形凶兽，复杂多段攻击模式 |
| **HundunEnemy** | 混沌BOSS敌人 | 大型终极BOSS敌人，终极凶兽，最强AI和最复杂攻击模式 |

## 表2 子弹系统类

| 类名称 | 主要功能 | 说明 |
|--------|--------|------|
| **IBullet** | 子弹抽象基类 | 所有子弹的抽象接口，定义虚函数：`update()`、`draw()`、`isActive()`、`getCollisionBox()`等 |
| **BasicBullet** | 普通子弹 | 标准直线运动子弹，命中敌人或边界消失，造成attackPower伤害 |
| **FireBall** | 火球弹 | 范围伤害子弹，击中目标后造成中心伤害+范围伤害(attackPower+10) |
| **LightningLine** | 闪电链弹 | 穿透伤害子弹，一束范围伤害(mul×attackPower+30)，带视觉效果 |

## 表3 游戏管理类

| 类名称 | 主要功能 | 说明 |
|--------|--------|------|
| **GameEntityManager** | 实体管理器 | 管理游戏中所有角色和子弹，提供添加/删除/获取实体、碰撞检测、批量更新等功能 |
| **GameProgressManager** | 进度管理器 | 管理游戏进度、波次生成、难度曲线、得分统计、游戏状态转换(初始化/进行/暂停/结束) |
| **GamePerkCardManager** | 卡牌管理器 | 管理游戏中的增益卡(Perk Card)系统，提供卡牌生成、选择、效果应用等功能 |

## 表4 核心虚函数(IRole接口)

| 函数名称 | 主要功能 | 调用时机 |
|--------|--------|---------|
| **init()** | 初始化角色 | 角色创建后立即调用，执行缓慢进场动画 |
| **think()** | AI决策逻辑 | 每帧调用(约10ms)，根据当前状态和环境决定下一步行动 |
| **doAction()** | 执行动作 | 每帧调用，执行think()决定的动作(移动、射击、特殊技能等) |
| **drawRole()** | 绘制角色 | 每帧调用，将角色图像绘制到OLED屏幕 |
| **die()** | 死亡处理 | 角色血量≤0时调用，执行死亡动画和掉落物品等 |
| **shoot()** | 发射子弹 | 由doAction()调用，根据BulletType创建子弹并加入管理器 |
| **move()** | 移动角色 | 由doAction()调用或AI系统调用，移动角色同时处理碰撞 |
| **takeDamage()** | 受伤处理 | 被子弹击中时调用，扣血并应用伤害效果 |
| **update()** | 更新状态 | 每帧调用(由GameEntityManager调用)，更新冷却、热量、计时器等 |

## 表5 主要游戏数据结构

| 数据结构 | 主要功能 | 包含内容 |
|---------|--------|---------|
| **RoleData** | 角色基础数据容器 | healthData(血量)、attackData(攻击)、spatialData(位置)、heatData(热量)、deathData(死亡)、actionData(动作)等 |
| **HealthData** | 血量系统 | 当前血量、最大血量、回血信息、受伤计时器 |
| **AttackData** | 攻击系统 | 攻击力、射击冷却、子弹速度、子弹范围、伤害倍率、碰撞伤害 |
| **SpatialData** | 空间信息 | 当前位置、参考位置、大小、移动速度、边界处理 |
| **HeatData** | 热量系统(玩家) | 最大热量、当前热量、单发热量消耗、冷却速率 |
| **ActionData** | 动作系统 | 当前状态(IDLE/MOVE/ATTACK等)、攻击模式(MODE_1/2/3) |
| **CollisionBox** | 碰撞体 | 矩形碰撞范围，用于碰撞检测 |

## 表6 游戏循环与控制流

| 函数/过程 | 主要功能 | 说明 |
|---------|--------|------|
| **main()** | 主函数 | STM32 HAL库初始化后的主程序入口，启动FreeRTOS多线程 |
| **gameLoopTask()** | 游戏主循环 | FreeRTOS任务(threads.cpp)，约10ms周期执行一次，调度游戏逻辑更新 |
| **gameUpdateTask()** | 游戏更新 | FreeRTOS任务，更新所有角色和子弹状态，检测碰撞，管理游戏进度 |
| **gameDrawTask()** | 游戏绘制 | FreeRTOS任务，每帧调用所有角色的drawRole()并更新OLED显示 |
| **controlDelayTime** | 控制周期 | 全局变量(10ms)，定义游戏逻辑更新时间间隔 |

## 表7 输入输出接口

| 函数名称 | 主要功能 | 说明 |
|---------|--------|------|
| **OLED_DrawImage()** | 绘制图像 | 在OLED屏幕指定坐标绘制图片 |
| **OLED_DrawLine()** | 绘制直线 | 绘制视觉效果线条(如冲锋轨迹、射线等) |
| **OLED_DrawRectangle()** | 绘制矩形 | 绘制矩形(如迷雾效果、UI边框等) |
| **OLED_ShowString()** | 显示文本 | 在屏幕显示ASCII字符(如得分、生命值等) |
| **key_scan()** | 按键扫描 | 物理按键输入处理，检测玩家操作(上下左右、射击等) |
| **getPlayerRole()** | 获取玩家 | GameEntityManager提供，获取当前玩家角色指针 |
| **getAllRoles()** | 获取所有角色 | GameEntityManager提供，遍历所有角色列表 |
| **getAllBullets()** | 获取所有子弹 | GameEntityManager提供，遍历所有子弹列表 |

## 表8 游戏参数系统

| 系统名称 | 主要参数 | 说明 |
|---------|--------|------|
| **冷却系统** | shootCooldownResetTime / shootCooldownSpeed | 射击冷却计算：冷却时间(ms) = resetTime / speed |
| **热量系统(玩家)** | maxHeat / heatPerShot / heatCoolDownRate | 热量管理，限制玩家连续射击，冷却周期约2000ms |
| **伤害系统** | attackPower / bulletDamageMultiplier / collisionPower | 多层伤害机制(基础伤害+倍率+碰撞伤害) |
| **子弹热量消耗** | 普通子弹×1 / 火球弹×2 / 闪电链×1.5 | 不同子弹类型的热量成本 |
| **波次生成** | 敌人数量 / 敌人类型 / 难度等级 | 根据游戏进度动态生成敌人波次 |
| **死亡动画时间** | 各敌人DeadTime常数(250-500ms) | 角色死亡后的动画持续时间 |

## 表9 STM32 HAL外设接口

| 外设接口 | 主要功能 | 说明 |
|---------|--------|------|
| **SSD1306 OLED** | 图形显示 | 128×64像素显示屏，显示游戏画面、UI信息 |
| **GPIO(按键)** | 输入控制 | 物理按键采集，玩家操作输入(上下左右移动、射击) |
| **I2C** | 通讯接口 | OLED屏幕通讯协议 |

| **UART/SPI** | 串口通讯 | 可选扩展(调试输出、无线通讯等) |

## 游戏流程图

```
初始化 → FreeRTOS启动多任务 → 游戏循环(10ms周期)
    ↓                              ↓
 HAL初始化              ┌─────────┼──────────┐
 OLED初始化             │         │          │
 GPIO初始化        gameLoopTask gameUpdate gameDrawTask
 按键初始化             │    Task    Task     │
 系统时钟配置           └─────────┼──────────┘
                                 ↓
                       更新角色→检测碰撞→绘制→游戏结束判定
```

## 关键设计特点

1. **多继承架构**: 所有角色通过IRole接口实现统一的行为规范
2. **分离渲染**: drawRole()独立一个任务，确保绘制流畅
3. **热量限制**: 玩家热量系统平衡游戏难度，防止过度连射
4. **AI分层**: 普通敌人简单逻辑，精英敌人中等复杂度，BOSS极高复杂度
5. **FreeRTOS多任务**: 并发处理游戏逻辑、输入采集、显示刷新
6. **神话元素**: 敌人设计基于中国古代山海经神话设定，各具特色
